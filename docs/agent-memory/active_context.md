# Active context

Milestone 1 is implemented as a Rust 2024 library and CLI. `gcdgold extract` reads canonical raw `MODE1/2352` and `MODE2/2352` BINs directly into a version-bound YAML manifest, a compact `.system` asset, ordinary ISO 9660 payload files, and, for Mode 2 XA, explicit indexed assets for mixed Form 1/Form 2 extents. `gcdgold build` regenerates ISO layout, raw sector framing, MSF, EDC, and ECC. A project extracted and rebuilt without edits must reproduce its source BIN byte-for-byte.

Primary ISO entries can preserve omitted `;1` file versions, bounded non-XA System Use prefixes (including prefixes before a trailing XA extension), and directory-local dot/parent recording-time and System Use overrides. Zero-length and out-of-image file records may be `record_only`; exact duplicate ordinary extents retain one physical owner. Descriptor support includes nonstandard volume-set/sequence values, space-padded Joliet escape sequences, final-NUL/space Joliet string padding, aliased Joliet and primary path-table pointers, and duplicate primary path tables inside a Joliet metadata layout. Mode 1 can preserve sparse eight-byte reserved-field runs before ECC generation, and Mode 2 tracks may contain explicitly authored protected zero Mode 1 gaps. The August 2026 PC-data-track probe now round-trips Graphic Artist Tools 1.8, Technical Reference 1.8, GE'G Disc 1, and Winning Post 4 track 01 exactly. The remaining CodeWarrior/Lightwave/Spider-Man/Tomb Raider/GEG+/Die Hard probes expose nonzero hybrid or interleaved content between semantic ISO metadata/extents; they remain explicitly unsupported until a typed physical representation is designed. King's Quest V Alt 2 is High Sierra (`CDROM` descriptors), and Winning Post tracks 36/37 are audio data rather than supported CD-ROM data tracks.

Raw-sector detection, protection validation, and sector generation are implemented in safe Rust; gcdgold has no `ecmlib` dependency. EDC uses the `crc` crate's named `CRC_32_CD_ROM_EDC` catalog algorithm, while ECC remains native. ECC's forward/backward Galois-field tables are derived once at compile time, and fixed-size monomorphized P/Q paths share the same core calculation for validation and generation. Extraction performs ordered Rayon classification across non-overlapping raw sectors, selects the earliest indexed error deterministically, and then constructs parsed sector copies in parallel. Build drafts every sector sequentially in LBA order with an explicit protection policy, finalizes EDC/ECC in place across non-overlapping sectors through Rayon's automatic pool, and only then applies Redump fills and raw patches. Mode 1 is selected from the uniform track mode, requires zero unrepresented reserved bytes plus valid EDC and header-addressed ECC, and distinguishes zero payload as a protected Mode 1 gap. Mode 2 Form 2 is selected solely by the primary XA subheader bit and records computed-EDC validity independently; non-Form-2 sectors are recognized as exact raw/XA gaps, valid Form 1 with zero-address ECC, or the bounded recorded-header ECC gap variant.

User-facing CLI help is intentionally format-neutral: gcdgold extracts and authors CD-ROM data tracks. Help descriptions must not advertise the current raw mode, sector size, XA subset, or BIN implementation as the permanent product boundary.

Repository testing convention: do not write tests for anything under `scripts/`. Product behavior remains covered by Rust library and CLI tests outside that directory.

The project is in active development. Do not preserve backward compatibility for schema, CLI, or behavior changes unless the user explicitly requests compatibility for that change; remove superseded interfaces and reject their old forms.

The ISO physical-placement sequence is named `iso9660.layout` because it contains ordinary files, directory extents, XA extents, and gaps. The superseded `iso9660.files` key is not accepted.

Extraction has one compact YAML serialization. The removed `--include-defaults` flag is rejected. Required root `gcdgold.version` records the exact Cargo package version of the extracting binary; build rejects a missing, non-string, unknown, or nonmatching version before reading project assets. `track` and `track.mode` are likewise mandatory and always emitted; other default-valued fields continue to be omitted.

A schema redundancy audit has consolidated entry references and ISO metadata/path-table subheaders. Remaining candidates include deriving `path_table_size` when raw path-table hex is present, folding named-versus-custom Application Use siblings into one value, inferring system Form 1 count from an explicit `sector_layout`, and making ordinary gap defaults track-mode-aware. Joliet also conditionally makes primary `path_table_order` ineffective and forces `path_table_copies: single`, so those combinations need consolidation or explicit rejection.

The manifest is authoritative and editable. The first filesystem entry is the root with `path: .`; `entries` order controls directory-record order. The `layout` sequence declares file membership and complete physical extent order. `{directory: PATH}` pins a non-root directory extent, `{gap: N}` inserts zero-payload Form 2 sectors, `{gap: N, kind: form1, subheader: ...}` preserves zero-payload protected Form 1 separators, and a final `{gap: N, kind: xa}` represents the raw XA tail. Every host asset that authors sectors is owned by `layout`: ordinary path items carry optional `source` plus `sha1`, indexed path items carry nested `xa_assets`, and unreferenced `xa_extent` items reuse the same nested XA asset structure. Each nested asset is `{path, sha1?}`; Form 1, Form 2, and index are required together, while gap index is optional. Exceptional ISO entries use one required-kind `reference: {kind, extent, length}` object. `layout` references are interleaved/Form-2 XA files fully covered by one indexed physical `xa_extent`; extraction can consolidate connected all-Form-2 or mixed Form-1/Form-2 overlap unions this way. `record_only` preserves a nonempty non-CDDA file record without claiming physical content, including extent-zero, out-of-range, and conflicting records. `external` is reserved for XA CDDA files, and `directory` preserves a non-root childless zero-length directory record without allocating a directory extent. Referenced entries never also appear as authored file paths in `iso9660.layout`. Ordinary file sizes otherwise come from their host assets.

Track manifests always include `mode`; start MSF `00:02:00`, computed Form 2 EDC, and compliant final ECC remain omitted defaults. Trailing space is no longer a track parameter; every trailing gap is an explicit final `layout` item. `noncompliant_trailing_ecc: true` reproduces the recorded-header ECC variant on the final raw XA-gap sector and is invalid without one. Optional `track.redump_0x55` stores ordered physical runs as signed absolute CD LBAs and sector counts for the Redump damaged-sector convention: sync, monotonic MSF, and mode remain valid while every byte from raw offset 16 through 2,351 is `0x55`. Extraction substitutes protected zero Mode 1 or Mode 2 Form 1 DATA blocks as the editable semantic view, excludes marked positions from framing/subheader validation and inference, and reapplies the `0x55` bodies after canonical generation. These runs preserve ownership and allocation anywhere in the track. Optional `track.patches` stores strictly ordered full 2,352-byte raw sectors as signed absolute CD LBAs plus whitespace-tolerant lowercase hex. Build resolves both representations relative to `frame(track.start_msf) - 150`, applies structural `0x55` fills first, and always installs every declared complete raw patch last. Users omit patches by removing them from a copy of the manifest; the removed `build --no-patches` switch is rejected.

Canonical Mode 1 is a first-class `track.mode: 1` layout. The raw parser requires one uniform sector mode, canonical Mode 1 EDC/ECC, zero reserved bytes, monotonic MSF, and 2,048-byte logical payloads at raw offset 16. Nonzero reserved bytes may have coherent ECC but remain unsupported because the manifest cannot preserve them. Mode 1 gaps use `{gap: N, kind: mode1}` and regenerate fully protected zero-payload Mode 1 sectors; unreferenced zero runs are discovered from physical placement rather than blindly stripping zero payloads from the end of a file. Mode 1 manifests reject XA sector-framing policies, Form 2 gaps, sidecars, and unreferenced XA extents while retaining ordinary XA System Use directory metadata. Full raw-sector patches are mode-independent. Raw-zero terminal runs remain mode-independent. Primary and Joliet descriptors may use bounded `file_structure_version: 0`; the standard value 1 is omitted and other values remain rejected.

The PSX system area is always 16 sectors. The canonical compact form is a contiguous Form 1 prefix followed by a zero-payload Form 2 suffix, including homogeneous all-Form-1 and all-Form-2 layouts. Noncanonical but structured ordering uses run-length `sector_layout` items with `form1`, `form2`, and `xa_gap` kinds; the run counts must total 16 and the Form 1 count must match `form1_sectors`. Extraction concatenates Form 1 payloads in physical order and trims trailing zero bytes into the `.system` asset. Build resolves `form1_sectors: auto` from the current asset size or honors an explicit count, consumes compact payload blocks at each declared Form 1 position, and generates Form 2 or XA-gap sectors at the other positions. Optional `final_form1_subheader: end_of_file_data` preserves the coherent variant whose physically last Form 1 system sector carries DATA plus EOF. Sparse `form1_framing` records use absolute system-sector indexes and preserve primary and duplicated subheaders for individual nonstandard Form 1 sectors while payload and protection remain structured and regenerated. Arbitrary nonzero/damaged Form 2 system sectors remain unsupported as editable semantics; the four approved malformed-sector fingerprints recover through a canonical semantic slot plus an inline raw-sector patch.

ISO 9660 structure is regenerated deterministically with the first PVD at LBA 16, ordered physical extents, and code-owned fixed directory-record fields. The omitted `primary_volume_copies: 1` writes one PVD; values 2 and 3 reproduce that many byte-identical PVD copies before the terminator and shift subsequent metadata accordingly. `primary_volume.u16_encoding: little_endian_only` preserves the narrow family whose three fixed PVD 16-bit values have correct little-endian halves and zero big-endian halves; mixed encodings remain rejected. `path_table_copies: single` preserves the coherent layout with one required little-endian and one required big-endian table; the omitted default `duplicate` writes both optional copies too. The omitted `path_table_order: little_endian_first` controls physical endian-table order independently, while `big_endian_first` preserves the Action Replay family. A noncanonical recorded path-table length uses `path_table_size`; when the declared logical path-table payload differs from the generated directory hierarchy, paired `path_table_little_hex` and `path_table_big_hex` fields preserve exactly that bounded payload and require identical optional copies. `path_table_subheader` is one scalar-or-map field: named policies retain canonical/final-sector behavior, while an explicit Form-1 subheader map applies identically to every block of every present copy. Explicit directory items reproduce authored directory placement even when a file physically precedes its parent directory; lazy placement remains a compatibility fallback for hand-authored manifests. The omitted `directory_record_packing: fill` uses every record that fits, while `avoid_exact_fit` preserves mastering layouts that move a record to the next sector when it would exactly consume the remaining bytes. Entry-local `directory_slack: {offset, hex}` preserves a trimmed nonzero region after the final generated directory record; build rejects overlap with records or escape from the allocated directory extent. Valid PVD/directory timestamps remain human-readable YAML; invalid fixed-width timestamp bytes use `hex:<bytes>` in the same fields and rebuild exactly. Primary identifiers are inferred directly: ISO Level 1 names and supported printable ASCII extensions such as `~`, `-`, `!`, lowercase, long names, or dotted directories round-trip without a manifest policy. Traversal, separators, backslashes, and non-ASCII identifiers remain rejected. Three named CD-XA Application Use variants cover the canonical signature, revision `1 1`, and the `XCD322.1 (13` mastering suffix; `CD Rep 2.0.131` remains a separate named variant whose deterministic trailing directory-record padding convention is reproduced. Noncanonical fixed 512-byte Application Use regions use `primary_volume.application_use_hex`, which cannot be combined with a nondefault named variant. Optional `primary_volume.reserved_hex` preserves a bounded nonzero prefix of the PVD's 653-byte reserved region. Fixed PVD invariants otherwise remain code-owned. `primary_volume.root_directory_identifier: parent` preserves the repeated PVD root-record identifier quirk, while `root_directory_record_length` preserves an explicitly overlong record that aliases following PVD fields. `metadata_subheader` likewise accepts a named scalar (`data`, `end_of_file_data`, or `iso_metadata`) or one explicit uniform Form-1 map for all governed metadata sectors. The removed `metadata_framing_subheader` and `path_table_framing_subheader` siblings are rejected. Optional `primary_volume.volume_space_size` preserves any nonzero recorded logical size independently from the authored physical layout, including values smaller than record-only references or the physical BIN and larger values needed by external references.

Additional bounded ISO policies cover the latest non-XA mastering family. `path_table_padding` inserts canonical raw XA-gap sectors after every present path-table copy and makes the physical copy stride explicit. `primary_volume.root_directory_recording_time` preserves a PVD-root timestamp that differs from the filesystem root entry. `directory_parent_recording_time: current` makes every non-root `..` record use the current directory timestamp instead of its parent's timestamp; extraction accepts only a consistent disc-wide choice.

One ISO Type-2 Joliet supplementary volume is now supported as a complete secondary filesystem rather than an opaque descriptor. `supplementary_volumes` stores the `%/@`, `%/C`, or `%/E` level, descriptor flags and fields, its own UCS-2BE entries, XA System Use policy, and independent little-/big-endian path tables. Each Joliet file names the primary file that owns its identical extent and length through `source`; `omit_version` preserves file identifiers without `;1`. `metadata_layout` explicitly orders the four primary/Joliet path tables, the two contiguous directory groups, and any canonical zero gaps. Metadata gaps store only their sector count; build derives protected Mode 1 versus XA-gap sectors from `track.mode`. `directory_length_policy` distinguishes allocated-block directory lengths from exact packed-record lengths. Descriptor padding remains structured through zero-fill policies, a bounded raw Volume Set Identifier field for the observed mixed zero/space anomaly, and three bounded odd bytes for the 37-byte file-identifier fields. A PVD may also carry a structured Joliet escape sequence independently. The volume terminator retains ordinary metadata framing; only Type 1 and Type 2 descriptors use PVD framing.

CD-XA System Use fields are structured through optional entry `xa` metadata: group ID, user ID, the lower eleven permission bits, named high-bit attributes, file number, logical-length encoding, and semantic framing overrides. The omitted global `xa_system_use: true` writes the 14-byte XA extension on every filesystem directory record; `false` preserves coherent images that omit it everywhere while leaving physical sector framing independently structured. An ordinary primary file may use entry-local `xa_system_use: false` to omit the extension inside an otherwise XA filesystem; omission of the field inherits the global policy, while explicit `true`, directory use, dot-record omissions, and use under global `false` are rejected. Directory records preserve both supported ISO flags, `hidden` and `associated`; the associated bit is valid on files and directories. ISO flags remain authoritative for entry kind: directories may coherently omit the XA directory attribute, while files still cannot claim it. Entry XA file numbers drive generated ordinary file and directory sector subheaders. Mixed extents are identified by `interleaved`/`mode2_form2` attributes, explicit layout sidecars, or observed Form 2/XA-gap sectors during extraction. Attributes may be omitted when the physical stream proves the mixed layout. Authored indexed files declare their secondary assets on the corresponding layout path:

```yaml
path: PATH.STR
xa_assets:
  form1:
    path: PATH.STR.XA1
    sha1: ...
  form2:
    path: PATH.STR.XA2
    sha1: ...
  index:
    path: PATH.STR.XAI
    sha1: ...
  gap_index:
    path: PATH.STR.XAG
    sha1: ...
```

No ordinary host asset is created at the mixed entry's ISO path. `.XA1` consists of fixed 2,056-byte records: four primary subheader bytes, four duplicated-subheader bytes, and 2,048 Form 1 payload bytes. `.XA2` consists of fixed 2,332-byte records with the same eight framing bytes and a 2,324-byte Form 2 payload. `.XAI` is a strictly increasing sequence of little-endian `u32` Form 2 positions relative to the start of the extent. Optional `.XAG` uses the same index encoding for canonical zero XA-gap positions; XAI and XAG positions must not overlap. Extraction preserves both subheader copies and every payload byte exactly; build consumes indexed Form 2 and gap positions and a Form 1 record everywhere else. Record streams must be consumed completely.

The same indexed assets now cover three narrow physical cases beyond attribute-declared mixed files. A file whose primary/duplicated Form 1 subheaders cannot be expressed by the canonical, DATA, DATA+EOF, or all-metadata policies is automatically promoted to indexed assets; optional `xa.logical_length` retains a non-sector-aligned ISO directory-record length. An unreferenced `xa_extent` uses the same framed streams without inventing an ISO entry. A directory may use `xa.framing_subheader` as the exact replacement for the DATA-framed prefix of `data`, `end_of_file_data`, or `data_until_final`; its logical directory payload is still regenerated.

Indexed files may also declare numeric `xa.length_encoding: 2336`; the default unit `2048` is omitted. Their XA1/XA2/XAI/XAG index count remains the sole authority for physical allocation, while primary and matching Joliet directory records write `sector_count * 2336` as the exact recorded file length. The setting cannot be combined with `logical_length` and requires all three indexed assets. Mode 2 XA extraction infers it only for a nonempty recorded length exactly divisible by 2,336 when the resulting physical extent stays at or before the next file/directory boundary but ordinary 2,048-byte ceiling arithmetic would cross that boundary. Extraction then clears spurious allocation padding, changes the parsed placement length to its physical `sector_count * 2048`, and prepares indexed assets before overlap fallback.

Sector form classification depends solely on raw mode 2 and the primary subheader's Form 2 bit. Duplicate-copy agreement, coding info, channel, EOF, payload contents, and EDC policy do not affect classification. For indexed mixed files, every other primary and duplicate subheader byte is opaque reconstruction data. Sector generation accepts distinct subheader copies and computes protection around those exact bytes. No cadence, channel-slot, XA-ADPCM, or coding-info interpretation remains.

Non-interleaved Form 1 files remain payload-only ordinary host files when their framing is coherent. Their primary and duplicate subheaders, ordinary zero padding, MSF, EDC, and ECC are generated programmatically. A nonzero prefix in the unused tail of a file's final 2,048-byte allocation block is preserved as entry-local `allocation_padding_hex`; it is trimmed after the last nonzero byte and is invalid for aligned, fixed-reference, directory, or indexed-XA entries. Canonical framing remains the default, while named entry policies preserve coherent all-DATA, DATA-until-final, final DATA+EOF, and all-ISO-metadata variants at file and directory scope. The DATA+EOF-final policy is also valid for directories and path tables. Entry XA file number is applied without retaining raw sectors. A zero-payload protected Form 1 gap can carry any explicit non-Form-2 subheader with matching copies, and extraction splits a mixed zero gap into ordered Form 1 and Form 2 runs. Adjacent Form 1 gaps remain distinct when their explicit subheaders differ; only consecutive identical gaps are redundant. Entry, global metadata, present-path-table, directory custom-prefix, file-sidecar, unreferenced-extent, and sparse system framing cover the corresponding observed mastering variants. Unrepresented anomalies remain explicit errors until their exact collection pattern is analyzed; corruption is no longer categorically excluded from structured or bounded-hex representation.

All manifest and secondary-asset paths are relative to `--data-dir`. An ordinary `layout` path may use optional `source` to name a host asset independently from its ISO path; omission keeps the identity mapping. The CLI keeps asset-root and output-location concerns independent: omitted `--manifest` writes the image basename with `.yaml` in the current directory, omitted build `--image` writes the manifest basename with `.bin` there, and `--data-dir` continues to default to `.` without depending on either input's parent. Explicit output paths remain authoritative. Successful extraction and build reports are human-oriented heading-and-label blocks on stdout and include their output path; recovery and SHA-1 warning blocks remain on stderr, with one blank line between multiple warnings. These reports are not a machine-readable compatibility protocol. Extraction/build reject traversal, absolute paths, symlinks, unsafe parent layouts, type conflicts, and duplicate authored host destinations. Without `--overwrite`, extraction reuses an existing regular asset when its SHA-1 matches and otherwise selects the first available or matching member of the same numeric filename family, rewriting ordinary `source`, `system_area.path`, or the relevant nested XA asset path. A terminal decimal suffix increments directly (`FILE.1` to `FILE.2`) rather than nesting. Existing real ISO directories are reusable. `--overwrite` retains nominal destructive asset replacement. Extraction always plans and writes a complete editable project; the removed `extract --manifest-only` switch is rejected. It performs no private reconstruction build or source comparison: the immutable source-track SHA-1 is computed once before recovery selection and reused for `track.sha1` and the extraction report, while the compact system asset, resolved ordinary authored source, and every layout-owned XA1/XA2/XAI/XAG asset are hashed separately before the final manifest is serialized and all assets are written. The removed `extract --include-hashes` switch is rejected because hashes are unconditional. References, directories, gaps, and external CDDA records receive no hash because they own no host asset in the data track. Build uses a synchronized temporary BIN and still rejects stale temporary outputs. It accepts case-insensitive 40-digit hexadecimal expectations, rejects malformed fields, compares resolved host assets before authoring, and compares the final track after Redump fills and all declared patches. Every present mismatch is retained in deterministic `BuildReport` order and printed by the CLI. System-area and asset mismatches are advisory only. A present mismatched `track.sha1` is also printed, leaves the complete output installed, and makes the CLI exit nonzero; an absent track hash performs no comparison and does not affect success.

`scripts/test_rom_catalog.py` is the sequential collection validation runner. With no arguments it loads `test_rom_catalog.toml` from the current working directory when that path exists, otherwise it falls back to `scripts/test_rom_catalog.toml` beside the runner; explicit `--config PATH` overrides both. Four required TOML strings name the gcdgold executable, ROM directory, append-only failure CSV, and passed-path ledger. Optional `manifests` names a flat persistent YAML directory, and optional `extracted_projects` names a flat root of retained editable projects; relative paths resolve from the config directory. The removed `output` and `temporary_directory` keys are rejected, and disposable work always uses Python's system temporary directory. The tracked `.toml.example` is copied to the ignored local config. Every invocation searches all top-level case-insensitive CUE files, scans every track declaration, ignores AUDIO, and selects every data track whose mode ends in `/2352`. A selected data track must be isolated in its own FILE; a FILE containing multiple TRACK declarations is rejected because the runner does not slice CUE INDEX ranges. Later valid tracks remain discoverable after an unsupported mode, and identical resolved BIN paths referenced by multiple sheets are processed once. The UTF-8 passed ledger contains one canonical ROM-relative POSIX data-track path per line, is the only scheduling state, preserves order, and is validated for empty, duplicate, absolute, traversal, and ROM-root-escaping entries. Missing passed ledgers begin empty. Each discovered path absent from the passed set is attempted; an exact build appends and fsyncs its path before printing PASS. The failure CSV is never read, validated, truncated, replaced, cleaned, or backed up: every failed attempt appends and fsyncs one fully quoted `[path, reason]` row before printing FAIL, so failed tracks retry and may accumulate historical rows. Interrupting an in-progress attempt records neither result, while already fsynced passes remain skipped. Track artifacts use the case-preserving BIN stem from the start of staging: extraction writes `Track.yaml`, so stem-derived assets are `Track.form1` or `Track.1.form1`, `Track.2.form1`, rather than retaining a temporary `disc` prefix. Standalone manifests are `manifests/Track.yaml`, while retained projects are `extracted_projects/Track/Track.yaml` with every extracted asset beside the YAML. Retained extraction stages within the configured root, rejects a root asset colliding with `Track.yaml`, installs only after extraction succeeds, replaces an existing complete project through a rollback-capable sibling backup, and remains available even if standalone-manifest installation or the subsequent build fails. Without `extracted_projects`, assets remain disposable. Same-stem tracks run independently and overwrite these artifacts sequentially; destination-name collisions do not affect reconstruction pass/fail, so only the last artifact remains. Each attempt builds once and trusts build's track-hash exit status. Per-ROM results use `[completed/total, rate: N.NN%] STATUS ...`, and summaries report previously passed tracks as skipped.
