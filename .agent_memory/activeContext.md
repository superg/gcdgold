# Active context

Milestone 1 is implemented as a Rust 2024 library and CLI. `gcdgold extract` parses a raw `MODE2/2352` BIN directly into an unversioned YAML manifest, a compact `.system` asset, and an ISO 9660 file tree. `gcdgold build` uses that editable project to recalculate path tables, lazy directory placement, file extents, PVD-derived values, XA framing, MSF, EDC, and ECC.

The manifest is authoritative: users may resize, rename, add, remove, or move Level 1 files and directories. The ISO root is the required first filesystem entry with `path: .`; it supplies PVD and root-directory metadata but is not treated as a host output or allocated as a child. Entry order preserves directory-record order. The `files` sequence interleaves `{path: ...}` file declarations with optional `{gap: N}` physical sector counts; path order controls file extents, path presence declares file membership, and entries absent from the sequence are directories. Physical authoring places the root immediately after the path tables, then scans `files`, allocating any missing ancestor directory before a pending gap and its following file; remaining empty directories are allocated breadth-first at the end. Gap counts must be nonzero, cannot be consecutive, and cannot end the list. The YAML contains neither SHA-1 fields nor a top-level `source` section; extraction and build reports may still display computed image SHA-1 values and sector counts, while untouched reconstruction is verified independently against reference BINs.

Track YAML is compact: `mode` accepts only `1`, `2`, and `2xa`, defaults to `2xa`, and is omitted at that default; `start_msf` defaults to and omits `00:02:00`; `trailing_gap` is a sector count that defaults to and omits `150`; boolean `form2_edc` is the track-wide policy, defaults to and omits `true`, with `true` calculating/writing EDC and `false` writing four zero bytes. `noncompliant_trailing_ecc` defaults to and omits `false`; when enabled, only the final raw track sector receives Form 1 ECC calculated with its recorded MSF/mode header instead of the standard zero Mode 2 address. When all five values are default, compact extraction omits the entire `track` node and deserialization restores it. Raw sector size is the code-level constant 2352 and is absent from YAML. Mode 1 and non-XA Mode 2 values parse as valid schema choices but are explicit build-time unsupported-feature errors because the current sector parser/writer implements Mode 2 XA only.

`extract --include-defaults` switches only YAML serialization to an explicit-default view. It emits the track defaults, empty/default PVD fields, and complete per-entry XA defaults including IDs, resolved attribute flags, file number, and nullable Form 2 sidecar. It composes with `--manifest-only` and `--overwrite`; the existing library `extract` function retains compact output, while `extract_with_options` exposes the serialization choice.

Primary-volume text identifiers default to an empty string and are omitted from compact YAML when empty; `--include-defaults` restores those empty fields for debugging. Volume-set size 1, volume sequence number 1, logical block size 2048, and file-structure version 1 are code-level PVD invariants absent from every manifest view. The 512-byte Application Use area is also code-owned: it is zero-filled except for the `CD-XA001` signature at PVD byte offset 1024. Extraction validates these bytes and authoring writes them directly; legacy `application_use_hex` manifests are rejected.

PVD creation, modification, expiration, and effective times use human-readable `YYYY-MM-DDTHH:MM:SS.cc±HH:MM` strings. The representation preserves centiseconds and the signed ISO 9660 quarter-hour timezone byte. An on-disc unspecified timestamp (`0000000000000000` plus zero offset) maps to `null`, is omitted from compact YAML, and appears as `null` under `--include-defaults`; legacy `_time_hex` fields are rejected.

All ISO directory-record timestamps, including root and file records, use human-readable `recording_time: YYYY-MM-DDTHH:MM:SS±HH:MM`. These seven-byte values have no centiseconds, encode years as 1900–2155, and share the signed quarter-hour timezone policy; legacy recording-time hex fields are rejected. There is no ISO-level `defaults` node: every entry explicitly contains its recording time, including newly authored entries, so source timestamp tendencies remain visible.

Entry YAML omits currently fixed ISO directory-record mechanics: file version is always `1`; flags are `0` for files and the directory bit only for directories; file-unit and interleave-gap sizes are `0`; volume sequence number is `1`. Canonical 14-byte CD-XA System Use defaults remain code-owned: user/group IDs and file number are zero, attributes are `0x0d55` for files or `0x8d55` for directories, the signature is `XA`, and reserved bytes are zero. Nondefault records use a structured `xa` object with optional group/user IDs, named attribute flags, file number, optional `form1_subheader`, and associated Form 2 sidecar path. The PVD root record has no System Use data. Entry `source_length` is absent because ordinary file size comes from the host file, while a mixed XA file's directory length is derived from its combined Form 1 and Form 2 sector count.

ISO directory records carrying the XA `cdda` attribute are external references into later audio tracks rather than authored data-track payloads. They retain explicit top-level `extent` and `length`, are omitted from `files`, and never produce host assets. The PVD logical volume size is the furthest external extent end, while the emitted raw BIN sector count remains the data-track layout plus its trailing gap. Directories containing external CDDA references are allocated immediately after the root before local file data; this preserves 3D Lemmings' `L3DMUS` directory at LBA 23.

Mode 2 XA subheaders use typed `XaSubheader`/`XaSubmode` values throughout parsing and generation. A raw mode byte of 2 plus the primary XA subheader's `form2` bit classifies Form 2 independently of duplicated-copy validation or EDC policy. Computed Form 2 EDC is recognized by successful validation rather than by checking for nonzero stored bytes, so a valid computed value of zero remains computed. The author writes canonical templates for system, ISO metadata, ordinary files, and zero-payload physical gaps.

Mixed XA files are recognized from `mode2_form2` or `interleaved` attributes. Their primary host file concatenates Form 1 payloads, optional `xa.form1_subheader` stores a noncanonical reusable Form 1 framing template, and the final Form 1 EOF bit plus trailing zero-padding framing are generated programmatically. A `.XA` sidecar remains a sequence of fixed 2,328-byte records containing the unique four-byte XA subheader followed by the 2,324-byte Form 2 payload; sync, duplicate subheader, MSF, and EDC are regenerated. Build assumes PSX double-speed playback and derives cadence from XA audio coding info. The initial sorted logical channel set is assigned permanently to the final N cadence slots; a channel's Form 2 `end_of_file` vacates its assigned slot at the next group boundary without shifting other channels, and Form 1 sectors fill all unassigned slots. This reproduces both 3D Lemmings' single channel in slot 7 and Spyro's independently ending channels without an explicit interleave field.

Both `extract` and `build` refuse existing outputs by default and accept an explicit `--overwrite` flag. Extraction replaces only the manifest, compact system asset, listed ISO files, and declared `.XA` sidecars, reuses matching directories, preserves unlisted host files, and rejects symlink or type-conflicting destinations. Missing parent directories for explicit manifest and image output paths are created after destination preflight and before their files are opened; this also applies to `--manifest-only`. Build writes and syncs its temporary image before replacing an existing regular BIN and never overwrites a stale temporary output.

The PSX system-area model stores a trimmed contiguous Form 1 payload and regenerates the zero-payload Form 2 suffix. Its size is a code-level invariant of 16 sectors, and build derives the compact source length directly from the `.system` file rather than manifest metadata. Automatic and explicit Form 1 counts are supported; generated Form 2 sectors use the track-wide EDC policy.

The supplied 5,174-sector Tyco reference rebuilds byte-for-byte with SHA-1 `5b16aa056dee14eff92891c24ca7cf71d263077d`; its compact 24,576-byte `.system` asset has SHA-1 `df9b3d7f3678ef11ecd606d4c820074381506668`. The 268,743-sector Crash reference rebuilds byte-for-byte with SHA-1 `61ff4c9e8dcfb9e5d94d37f66330b69d08d6c914`. The 281,270-sector Spyro reference, including six interleaved streams and two physical Form 2 gaps, rebuilds byte-for-byte with SHA-1 `cf3ce6bedeb89dfbc40990336180f3b9b0f40d9f`. The 81,711-sector 3D Lemmings data track rebuilds byte-for-byte with SHA-1 `f713cdcb5d0e3d875031dbdc438dbbab0cdd3340`, including zeroed Form 2 EDC, mixed video/audio XA extents, external CDDA directory references, and recorded-header ECC on the final raw sector.

Current explicit exclusions are Mode 1 and non-XA Mode 2 authoring, authoring the audio-track payloads referenced by external CDDA records, subchannel data, multisession layout, Joliet, Rock Ridge, multi-extent files, non-audio or incompatible-cadence Form 2 sidecars, playback-speed selection other than the PSX double-speed assumption, duplicated XA subheader mismatches, nonstandard fixed PVD values, and nonzero Form 2 system payloads. The verification baseline is 74 passing library tests plus two CLI tests, clean formatting, and Clippy with warnings denied.
