# Active context

Milestone 1 is implemented as a Rust 2024 library and CLI. `gcdgold extract` parses a raw `MODE2/2352` BIN directly into an unversioned YAML manifest, a compact `.system` asset, and an ISO 9660 file tree. `gcdgold build` uses that editable project to recalculate path tables, breadth-first directory layout, file extents, PVD-derived values, XA framing, MSF, EDC, and ECC.

The manifest is authoritative: users may resize, rename, add, remove, or move Level 1 files and directories. The ISO root is the required first filesystem entry with `path: .`; it supplies PVD and root-directory metadata but is not treated as a host output or allocated as a child. Entry order preserves directory-record order. The following `files` list both declares which entry paths are files and preserves their physical extent order; entries absent from it are directories. The YAML contains neither SHA-1 fields nor a top-level `source` section; extraction and build reports may still display computed image SHA-1 values and sector counts, while untouched reconstruction is verified independently against the reference BIN.

Track YAML is compact: `mode` accepts only `1`, `2`, and `2xa`, defaults to `2xa`, and is omitted at that default; `start_msf` defaults to and omits `00:02:00`; `trailing_gap_sectors` defaults to and omits `150`; boolean `form2_edc` is the track-wide policy, defaults to and omits `true`, with `true` calculating/writing EDC and `false` writing four zero bytes; raw sector size is the code-level constant 2352 and is absent from YAML. Mode 1 and non-XA Mode 2 values parse as valid schema choices but are explicit build-time unsupported-feature errors because the current sector parser/writer implements Mode 2 XA only.

`extract --include-defaults` switches only YAML serialization to an explicit-default view, currently emitting `track.mode: 2xa`, `track.start_msf: 00:02:00`, `track.trailing_gap_sectors: 150`, and `track.form2_edc: true`. It composes with `--manifest-only` and `--overwrite`; the existing library `extract` function retains compact output, while `extract_with_options` exposes the serialization choice.

Primary-volume text identifiers default to an empty string and are omitted from compact YAML when empty; `--include-defaults` restores those empty fields for debugging. Volume-set size 1, volume sequence number 1, logical block size 2048, and file-structure version 1 are code-level PVD invariants absent from every manifest view. The 512-byte Application Use area is also code-owned: it is zero-filled except for the `CD-XA001` signature at PVD byte offset 1024. Extraction validates these bytes and authoring writes them directly; legacy `application_use_hex` manifests are rejected.

PVD creation, modification, expiration, and effective times use human-readable `YYYY-MM-DDTHH:MM:SS.cc±HH:MM` strings. The representation preserves centiseconds and the signed ISO 9660 quarter-hour timezone byte. An on-disc unspecified timestamp (`0000000000000000` plus zero offset) maps to `null`, is omitted from compact YAML, and appears as `null` under `--include-defaults`; legacy `_time_hex` fields are rejected.

All ISO directory-record timestamps, including root and file records, use human-readable `recording_time: YYYY-MM-DDTHH:MM:SS±HH:MM`. These seven-byte values have no centiseconds, encode years as 1900–2155, and share the signed quarter-hour timezone policy; legacy recording-time hex fields are rejected. There is no ISO-level `defaults` node: every entry explicitly contains its recording time, including newly authored entries, so source timestamp tendencies remain visible.

Entry YAML omits currently fixed ISO directory-record mechanics: file version is always `1`; flags are `0` for files and the directory bit only for directories; file-unit and interleave-gap sizes are `0`; volume sequence number is `1`. Canonical 14-byte CD-XA System Use data is also code-owned: user and group IDs are zero, attributes are `0x0d55` for files or `0x8d55` for directories, the signature is `XA`, and file number plus reserved bytes are zero. The PVD root record has no System Use data. Extraction validates these values and authoring generates them directly. Entry `source_length` is absent because extraction uses the directory record only to read the source extent, while build derives the authored length from the current host file.

Mode 2 XA subheaders use typed `XaSubheader`/`XaSubmode` values throughout parsing and generation but are not customizable in YAML. The author writes canonical templates in code: system and ordinary file Form 1 sectors use `DATA`; the PVD uses `END_OF_RECORD | DATA`; all other ISO metadata and final file sectors use `END_OF_RECORD | DATA | END_OF_FILE`; system Form 2 sectors use `FORM2`; numeric fields are zero. Extraction validates these rules and rejects nonstandard framing so template removal cannot compromise exact reconstruction. The typed structures and named flag serializer remain available for later streaming-file support.

Both `extract` and `build` refuse existing outputs by default and accept an explicit `--overwrite` flag. Extraction replaces only the manifest, compact system asset, and listed ISO files, reuses matching directories, preserves unlisted host files, and rejects symlink or type-conflicting destinations. Build writes and syncs its temporary image before replacing an existing regular BIN and never overwrites a stale temporary output.

The PSX system-area model stores a trimmed contiguous Form 1 payload and regenerates the zero-payload Form 2 suffix. Its size is a code-level invariant of 16 sectors, and build derives the compact source length directly from the `.system` file rather than manifest metadata. Automatic and explicit Form 1 counts are supported; generated Form 2 sectors use the track-wide EDC policy.

The supplied 5,174-sector reference image rebuilds byte-for-byte with SHA-1 `5b16aa056dee14eff92891c24ca7cf71d263077d`; its compact 24,576-byte `.system` asset has SHA-1 `df9b3d7f3678ef11ecd606d4c820074381506668`.

Current explicit exclusions are Mode 1 and non-XA Mode 2 authoring, audio/subchannel data, multisession layout, Joliet, Rock Ridge, multi-extent files, XA streaming/interleaving, nonstandard ISO/system XA framing, nonstandard fixed PVD or directory-record values, and nonzero Form 2 system payloads. The verification baseline is 47 passing tests plus clean formatting and Clippy with warnings denied.
