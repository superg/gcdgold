# Active context

Milestone 1 is implemented as a Rust 2024 library and CLI. `gcdgold extract` reads a raw `MODE2/2352` BIN directly into an unversioned YAML manifest, a compact `.system` asset, ordinary ISO 9660 payload files, and explicit indexed XA assets for mixed Form 1/Form 2 extents. `gcdgold build` regenerates ISO layout, raw sector framing, MSF, EDC, and ECC. A project extracted and rebuilt without edits must reproduce the source BIN byte-for-byte.

The manifest is authoritative and editable. The first filesystem entry is the root with `path: .`; `entries` order controls directory-record order. The `files` sequence declares file membership and complete physical extent order. `{directory: PATH}` pins a non-root directory extent, `{gap: N}` inserts zero-payload Form 2 sectors, and a final `{gap: N, kind: xa}` represents the raw XA tail. Entries absent from file-path items are directories, except external CDDA entries, which retain explicit `extent` and `length` references outside the authored data track. Ordinary file sizes come from their host assets.

Track defaults are compact: mode `2xa`, start MSF `00:02:00`, computed Form 2 EDC, and compliant final ECC are omitted. Trailing space is no longer a track parameter; every trailing gap is an explicit final `files` item. `noncompliant_trailing_ecc: true` reproduces the recorded-header ECC variant on the final raw XA-gap sector and is invalid without one. Optional `track.ppf` references a manually supplied, pre-protection PPF2 overlay beneath the data directory. Extraction never creates or references PPF files. Build validates and applies every manual PPF record to the canonical raw image, then regenerates protection for touched sectors. `--include-defaults` is an extraction-only diagnostic serialization view; it does not change authoring semantics.

The PSX system area is always 16 sectors. Extraction accepts a contiguous Form 1 prefix followed by a zero-payload Form 2 suffix, including homogeneous all-Form-1 and all-Form-2 layouts. It concatenates the Form 1 payloads and trims trailing zero bytes into the `.system` asset. Build resolves `form1_sectors: auto` from the current asset size or honors an explicit count, pads Form 1 content to that boundary, and generates the remaining Form 2 sectors using the track-wide EDC policy. Optional `final_form1_subheader: end_of_file_data` preserves the coherent variant whose last Form 1 system sector carries DATA plus EOF.

ISO 9660 Level 1 structure is regenerated deterministically with the PVD at LBA 16, one terminator, four path-table copies, ordered physical extents, and code-owned fixed directory-record fields. Explicit directory items reproduce authored directory placement; the earlier lazy placement remains a compatibility fallback for hand-authored manifests without them. Text identifiers and PVD/directory timestamps remain human-readable YAML. The two observed CD-XA Application Use signatures are named structured variants, and fixed PVD invariants remain code-owned. Optional `metadata_subheader: data` preserves the coherent variant where ISO metadata sectors use plain DATA subheaders. Optional `primary_volume.volume_space_size` is emitted only when the recorded ISO logical volume exceeds the size inferred from the authored data track and external CDDA references. It changes the PVD field without padding or resizing the BIN; Interactive4 requires `294418` while its data-track BIN contains 272,183 sectors.

CD-XA System Use fields are structured through optional entry `xa` metadata: group ID, user ID, the lower eleven permission bits, named high-bit attributes, and file number. Directory records also preserve the supported ISO hidden flag. Mixed extents are identified only by `interleaved` or `mode2_form2` directory attributes. Such entries must declare all three secondary assets:

```yaml
xa:
  form1: PATH.STR.XA1
  form2: PATH.STR.XA2
  index: PATH.STR.XAI
```

No ordinary host asset is created at the mixed entry's ISO path. `.XA1` consists of fixed 2,056-byte records: four primary subheader bytes, four duplicated-subheader bytes, and 2,048 Form 1 payload bytes. `.XA2` consists of fixed 2,332-byte records with the same eight framing bytes and a 2,324-byte Form 2 payload. `.XAI` is a strictly increasing sequence of little-endian `u32` Form 2 positions relative to the start of the extent. Extraction preserves both subheader copies and every payload byte exactly; build consumes the indexed Form 2 record at each listed position and a Form 1 record everywhere else. Record streams must be consumed completely.

Sector form classification depends solely on raw mode 2 and the primary subheader's Form 2 bit. Duplicate-copy agreement, coding info, channel, EOF, payload contents, and EDC policy do not affect classification. For indexed mixed files, every other primary and duplicate subheader byte is opaque reconstruction data. Sector generation accepts distinct subheader copies and computes protection around those exact bytes. No cadence, channel-slot, XA-ADPCM, or coding-info interpretation remains.

Non-interleaved Form 1 files remain payload-only ordinary host files. Their primary and duplicate subheaders, padding, MSF, EDC, and ECC are generated programmatically. Canonical framing remains the default, while named entry policies preserve coherent all-DATA and DATA-until-final variants for files and directories. The global metadata policy and system final-sector policy cover the corresponding coherent mastering variants. Extraction still rejects unrecognized, inconsistent, or apparently corrupt subheader patterns rather than silently preserving opaque sectors.

All manifest and secondary-asset paths are relative to `--data-dir`. Extraction/build reject traversal, absolute paths, symlinks, type conflicts, duplicate destinations, and collisions among ISO paths, system, PPF, XA1, XA2, and XAI assets. Extraction preflights all declared outputs before writing, creates missing parents, preserves unrelated host files, and writes only the manifest under `--manifest-only`. `--overwrite` replaces declared regular outputs only. Build uses a synchronized temporary BIN and still rejects stale temporary outputs.

Exact untouched reconstruction fixtures:

- Tyco: 5,174 sectors, SHA-1 `5b16aa056dee14eff92891c24ca7cf71d263077d`; compact system asset 24,576 bytes, SHA-1 `df9b3d7f3678ef11ecd606d4c820074381506668`.
- Crash: 268,743 sectors, SHA-1 `61ff4c9e8dcfb9e5d94d37f66330b69d08d6c914`.
- Spyro: 281,270 sectors, SHA-1 `cf3ce6bedeb89dfbc40990336180f3b9b0f40d9f`, including six mixed streams and physical Form 2 gaps.
- 3D Lemmings: 81,711 data-track sectors, SHA-1 `f713cdcb5d0e3d875031dbdc438dbbab0cdd3340`, including indexed mixed extents, external CDDA records, zero Form 2 EDC, and noncompliant final ECC.
- Interactive CD Sampler Volume 4: 272,183 data-track sectors, SHA-1 `124146d68022f1ba72b8221be60d1a086725af06`, including irregular form order and 5,726 duplicated-subheader mismatches preserved through XA1/XA2 assets without PPF.

`scripts/test_rom_catalog.py` is the sequential collection validation runner. With no arguments it loads `scripts/test_rom_catalog.toml`; `--config PATH` is its only override. The three required TOML strings name the gcdgold executable, ROM directory, and authoritative failure CSV, with relative paths resolved from the config directory. The tracked `.toml.example` is copied to the ignored local config. On the first run, the runner searches only top-level case-insensitive CUE files and collects every track mode ending in `/2352`, including multiple data tracks per CUE. Later runs process only the ROM-relative paths in the existing headerless two-column CSV. Every attempt extracts and rebuilds in an automatically removed system temporary directory and performs a streaming byte comparison. Each per-ROM console result and the summary show cumulative PASS and FAIL percentages across completed attempts. Passes disappear; extraction, build, size, byte, and input failures are streamed to `{output}.tmp` with their complete normalized diagnostic. A completed run atomically replaces `{output}`, after first atomically overwriting `{output}.bak` with the prior final CSV. The CSV is the source of truth; the runner creates no journals, fingerprints, or failure logs.

Current exclusions are Mode 1 and non-XA Mode 2 authoring, authored audio-track payloads behind external CDDA references, subchannels, multisession authoring, Joliet, Rock Ridge, multi-extent files, nonzero Form 2 system payloads, and semantic editing of framed XA1/XA2 records. PPF extraction remains disabled; any future automatic PPF construction requires an individually analyzed and manually approved anomaly class.

Catalog iteration now exactly reconstructs representative images for explicit directory placement, terminal Form 2 gaps, nondefault XA permissions, hidden entries, coherent entry/metadata/system subheaders, and the alternate standard Application Use signature. Random-looking or internally inconsistent variants are intentionally left unsupported as probable corruption, per the current collection-triage policy.

Verification baseline: 93 Rust library tests and two Rust CLI tests pass. The catalog runner is debug tooling under `scripts/` and intentionally has no automated tests. `cargo fmt --check`, Clippy across all targets/features with warnings denied, and `cargo test` are required before handoff.
