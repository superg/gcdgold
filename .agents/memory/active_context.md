# Active context

Milestone 1 is implemented as a Rust 2024 library and CLI. `gcdgold extract` reads a raw `MODE2/2352` BIN directly into an unversioned YAML manifest, a compact `.system` asset, ordinary ISO 9660 payload files, and explicit indexed XA assets for mixed Form 1/Form 2 extents. `gcdgold build` regenerates ISO layout, raw sector framing, MSF, EDC, and ECC. A project extracted and rebuilt without edits must reproduce the source BIN byte-for-byte.

The manifest is authoritative and editable. The first filesystem entry is the root with `path: .`; `entries` order controls directory-record order. The `files` sequence declares file membership and complete physical extent order. `{directory: PATH}` pins a non-root directory extent, `{gap: N}` inserts zero-payload Form 2 sectors, `{gap: N, kind: form1, subheader: ...}` preserves zero-payload protected Form 1 separators, and a final `{gap: N, kind: xa}` represents the raw XA tail. Entries absent from file-path items are directories, except external CDDA entries, which retain explicit `extent` and `length` references without authored payloads. Their references may be empty, use extent zero, or overlap the local data-track address range because the XA CDDA attribute keeps them semantically external. Ordinary file sizes come from their host assets.

Track defaults are compact: mode `2xa`, start MSF `00:02:00`, computed Form 2 EDC, and compliant final ECC are omitted. Trailing space is no longer a track parameter; every trailing gap is an explicit final `files` item. `noncompliant_trailing_ecc: true` reproduces the recorded-header ECC variant on the final raw XA-gap sector and is invalid without one. Optional `track.ppf` references a manually supplied, pre-protection PPF2 overlay beneath the data directory. Extraction never creates or references PPF files. Build validates and applies every manual PPF record to the canonical raw image, then regenerates protection for touched sectors. `--include-defaults` is an extraction-only diagnostic serialization view; it does not change authoring semantics.

The PSX system area is always 16 sectors. Extraction accepts a contiguous Form 1 prefix followed by a zero-payload Form 2 suffix, including homogeneous all-Form-1 and all-Form-2 layouts. It concatenates the Form 1 payloads and trims trailing zero bytes into the `.system` asset. Build resolves `form1_sectors: auto` from the current asset size or honors an explicit count, pads Form 1 content to that boundary, and generates the remaining Form 2 sectors using the track-wide EDC policy. Optional `final_form1_subheader: end_of_file_data` preserves the coherent variant whose last Form 1 system sector carries DATA plus EOF.

ISO 9660 structure is regenerated deterministically with the first PVD at LBA 16, ordered physical extents, and code-owned fixed directory-record fields. The omitted `primary_volume_copies: 1` writes one PVD; the supported nondefault value `3` reproduces three byte-identical PVD copies before the terminator and shifts subsequent metadata accordingly. `path_table_copies: single` preserves the coherent layout with one required little-endian and one required big-endian table; the omitted default `duplicate` writes both optional copies too. Explicit directory items reproduce authored directory placement even when a file physically precedes its parent directory; lazy placement remains a compatibility fallback for hand-authored manifests. The omitted `directory_record_packing: fill` uses every record that fits, while `avoid_exact_fit` preserves mastering layouts that move a record to the next sector when it would exactly consume the remaining bytes. Text identifiers and PVD/directory timestamps remain human-readable YAML. ISO Level 1 names remain the default; extraction selects explicit global `identifier_policy: nonstandard_ascii` when a source uses printable ASCII directory-record identifiers such as `~`, `-`, `!`, or a dotted directory name. Traversal, separators, backslashes, and non-ASCII identifiers remain rejected. Three named CD-XA Application Use variants cover the canonical signature, revision `1 1`, and the `XCD322.1 (13` mastering suffix; `CD Rep 2.0.131` remains a separate named variant whose deterministic trailing directory-record padding convention is reproduced. Fixed PVD invariants remain code-owned. `primary_volume.root_directory_identifier: parent` preserves the repeated PVD root-record identifier quirk. Optional `metadata_subheader: data`, `end_of_file_data`, and `iso_metadata` cover coherent global metadata framing. Path tables support DATA-until-canonical-final and DATA-until-DATA+EOF-final policies independently on every present copy. Optional `primary_volume.volume_space_size` preserves any logical size that still covers referenced content, including a value smaller than the physical BIN when a structured terminal gap follows the logical volume, or a larger value needed by external references.

CD-XA System Use fields are structured through optional entry `xa` metadata: group ID, user ID, the lower eleven permission bits, named high-bit attributes, and file number. Directory records preserve both supported ISO flags, `hidden` and `associated`; the associated bit is valid on files and directories. ISO flags remain authoritative for entry kind: directories may coherently omit the XA directory attribute, while files still cannot claim it. Entry XA file numbers drive generated ordinary file and directory sector subheaders. Mixed extents are identified by `interleaved`/`mode2_form2` attributes, explicit sidecar assets, or observed Form 2/XA-gap sectors during extraction. Attributes may be omitted when the physical stream proves the mixed layout. Such entries declare the three base secondary assets and an optional gap-position asset:

```yaml
xa:
  form1: PATH.STR.XA1
  form2: PATH.STR.XA2
  index: PATH.STR.XAI
  gap_index: PATH.STR.XAG
```

No ordinary host asset is created at the mixed entry's ISO path. `.XA1` consists of fixed 2,056-byte records: four primary subheader bytes, four duplicated-subheader bytes, and 2,048 Form 1 payload bytes. `.XA2` consists of fixed 2,332-byte records with the same eight framing bytes and a 2,324-byte Form 2 payload. `.XAI` is a strictly increasing sequence of little-endian `u32` Form 2 positions relative to the start of the extent. Optional `.XAG` uses the same index encoding for canonical zero XA-gap positions; XAI and XAG positions must not overlap. Extraction preserves both subheader copies and every payload byte exactly; build consumes indexed Form 2 and gap positions and a Form 1 record everywhere else. Record streams must be consumed completely.

Sector form classification depends solely on raw mode 2 and the primary subheader's Form 2 bit. Duplicate-copy agreement, coding info, channel, EOF, payload contents, and EDC policy do not affect classification. For indexed mixed files, every other primary and duplicate subheader byte is opaque reconstruction data. Sector generation accepts distinct subheader copies and computes protection around those exact bytes. No cadence, channel-slot, XA-ADPCM, or coding-info interpretation remains.

Non-interleaved Form 1 files remain payload-only ordinary host files. Their primary and duplicate subheaders, padding, MSF, EDC, and ECC are generated programmatically. Canonical framing remains the default, while named entry policies preserve coherent all-DATA, DATA-until-final, final DATA+EOF, and all-ISO-metadata variants at file and directory scope. The DATA+EOF-final policy is also valid for directories and path tables. Entry XA file number is applied without retaining raw sectors. A zero-payload protected Form 1 gap can carry any explicit non-Form-2 subheader with matching copies, and extraction splits a mixed zero gap into ordered Form 1 and Form 2 runs. Adjacent Form 1 gaps remain distinct when their explicit subheaders differ; only consecutive identical gaps are redundant. Entry, global metadata, present-path-table, and system final-sector policies cover the corresponding coherent mastering variants. Extraction still rejects unrecognized, inconsistent, or apparently corrupt subheader patterns rather than silently preserving opaque sectors.

All manifest and secondary-asset paths are relative to `--data-dir`. Extraction/build reject traversal, absolute paths, symlinks, type conflicts, duplicate destinations, and collisions among ISO paths, system, PPF, XA1, XA2, XAI, and XAG assets. Extraction preflights all declared outputs before writing, creates missing parents, preserves unrelated host files, and writes only the manifest under `--manifest-only`. `--overwrite` replaces declared regular outputs only. Build uses a synchronized temporary BIN and still rejects stale temporary outputs.

Known collection reconstruction cases, validated externally through the catalog runner:

- Tyco: 5,174 sectors, SHA-1 `5b16aa056dee14eff92891c24ca7cf71d263077d`; compact system asset 24,576 bytes, SHA-1 `df9b3d7f3678ef11ecd606d4c820074381506668`.
- Crash: 268,743 sectors, SHA-1 `61ff4c9e8dcfb9e5d94d37f66330b69d08d6c914`.
- Spyro: 281,270 sectors, SHA-1 `cf3ce6bedeb89dfbc40990336180f3b9b0f40d9f`, including six mixed streams and physical Form 2 gaps.
- 3D Lemmings: 81,711 data-track sectors, SHA-1 `f713cdcb5d0e3d875031dbdc438dbbab0cdd3340`, including indexed mixed extents, external CDDA records, zero Form 2 EDC, and noncompliant final ECC.
- Interactive CD Sampler Volume 4: 272,183 data-track sectors, SHA-1 `124146d68022f1ba72b8221be60d1a086725af06`, including irregular form order and 5,726 duplicated-subheader mismatches preserved through XA1/XA2 assets without PPF.

`scripts/test_rom_catalog.py` is the sequential collection validation runner. With no arguments it loads `scripts/test_rom_catalog.toml`; `--config PATH` is its only override. The three required TOML strings name the gcdgold executable, ROM directory, and authoritative failure CSV, with relative paths resolved from the config directory. The tracked `.toml.example` is copied to the ignored local config. On the first run, the runner searches only top-level case-insensitive CUE files and collects every track mode ending in `/2352`, including multiple data tracks per CUE. Later runs process only the ROM-relative paths in the existing headerless two-column CSV. The writer quotes both fields on every row for visual consistency, while the reader accepts any valid standard CSV quoting. Every attempt extracts and rebuilds in an automatically removed system temporary directory and performs a streaming byte comparison. Each per-ROM console result uses `[completed/total, rate: N.NN%] STATUS ...`, where rate is the cumulative pass percentage across completed attempts; the summary reports the same rate. Passes disappear; extraction, build, size, byte, and input failures are streamed to `{output}.tmp` with their complete normalized diagnostic. A completed run atomically replaces `{output}`, after first atomically overwriting `{output}.bak` with the prior final CSV. The CSV is the source of truth; the runner creates no journals, fingerprints, or failure logs.

Current exclusions are Mode 1 and non-XA Mode 2 authoring, authored audio-track payloads behind external CDDA references, subchannels, multisession authoring, Joliet, Rock Ridge, multi-extent files, nonzero Form 2 system payloads, and semantic editing of framed XA1/XA2 records. PPF extraction remains disabled; any future automatic PPF construction requires an individually analyzed and manually approved anomaly class.

Verification baseline: 104 Rust library tests and two Rust CLI tests pass without reading `data/` or creating image files. Raw-sector behavior is covered with in-memory byte arrays; workflow behavior is covered at manifest, layout, subheader, sidecar, protection, and path-preflight boundaries. Real-ROM round trips belong exclusively to manual exact-path probes and the catalog runner, which is debug tooling under `scripts/` and intentionally has no automated tests. `cargo fmt --check`, Clippy across all targets/features with warnings denied, and `cargo test` are required before handoff.
